# The core, as a vault carries it

This folder mirrors a vault's `.claude/scripts/`:

| Here | In a vault | Holds |
|------|------------|-------|
| `core/` | `.claude/scripts/core/` | The extension registry (`registry.ts`), its API types (`types.ts`), the public entry point extensions import (`index.ts`), what entry points open first (`context.ts`), and their tests |
| `lib/` | `.claude/scripts/lib/` | The core's libraries: `hook-io` (hook I/O and the output cap), `manifest` (the one parse of `vault-manifest.json`, frozen), `frontmatter-block` (where a note's frontmatter is: the one rule every reader goes through), `session-start` (the byte budget and its meter, and the manifest's readers, each with an `…Of` form that takes `openVault`'s parsed manifest), `project-dir` (vault-root discovery, exported to extensions), `om-mod` (the mod's flag protocol), `frontmatter` (write validation: required fields, `shouldSkipFile`), `prose-width` (the no-hard-wrap rule), `fences` (the one fence rule both of them and `wikilinks` read a note by), `atomic-write` (a whole note or none of it, exported to extensions), `instruction-files` (AGENTS.md as the one instruction file, the retired ones and its size caps, exported to extensions), `qmd` (a re-export of the qmd extension's, removed in #96), `wikilinks` (link targets, and a note's line regions and link offsets), `regex` |
| `extensions/qmd/` | `.claude/scripts/extensions/qmd/` | The qmd extension, first-party and optional (#70, #95): QMD's session-start notes as sections and its index refresh as effects (`index.ts`), the work behind them (`session.ts`, and `lib/refresh.ts` with its detached worker `refresh-run.ts`, lifted from obsidian-mind 0a58edf), its libraries (`lib/qmd.ts`, `lib/index-name.ts`), and their tests |
| `tests/` | `.claude/scripts/tests/` | The libraries' tests: `hook-io`, `project-dir`, `om-mod`, `frontmatter`, `prose-width`, `regex`, `wikilinks`, `line-regions`, `atomic-write-retry`, `fences`, `manifest-readers`, `frontmatter-block`, `injection-meter`, `qmd-reexports`. One frontmatter case is skipped: it checks a vault's own Work Note template against its manifest, which only obsidian-mind ships |

**`vendor-guard.ts` is the one hook entry point here.** It denies edits to vendored files and names the routes instead: an extension, a fix upstream, or a local patch (see [the vendor README](../vendor/README.md#the-write-guard-and-patch-begin)). A vault wires it as a PreToolUse hook on `Edit|Write|MultiEdit|NotebookEdit`, with the same walk up to `vault-manifest.json` its other hook commands use.

**Two contracts every vault shares, and that don't change:**
- `project-dir` finds the vault root by walking up from the project directory to the first folder holding `vault-manifest.json`, so a session started in a subfolder still finds its vault.
- `om-mod` reads the `om_mod` field a mod passes to a settings hook: `standdown` (the mod delivers this event: print nothing), `deliver` (print the context for the mod's instruction file) and `report` (return the Stop report as data).

The mod itself is still each vault's own; one template for every vault is [#47](https://github.com/breferrari/mindframe/issues/47).

**Two switches turn QMD's work off** (`extensions/qmd/lib/switches.ts`), each only with the exact value `off`: `VAULT_QMD` turns all of it off, and `VAULT_QMD_REFRESH` only the detached refresh, session start's update or bootstrap and the debounced worker, so a test run that sets it leaves no qmd worker behind; the probes and their notes still run (#94, #95, as obsidian-mind #338).

**Entry points start from `core/context.ts`.** `openVault(vaultRoot, event)` reads and parses `vault-manifest.json` once and loads the registry for that event, so no entry point parses the manifest itself. `migrationNotes(manifest)` gives the notes a session-start entry point passes to `formatInjectionSize` as `notes`, so a step a vault still has to take after an update shows on the meter line. `readManifest` never throws: a missing or malformed manifest means no extensions and the default budgets. `context.ts` is for entry points; extensions import only from `index.ts`.

A vault vendors this folder by copying it onto its `.claude/scripts/`, byte for byte, and records the copy in its `VENDOR.json`. The paths and imports (`../lib/x.ts`) are the same on both sides, so updating a vault's copy is a source swap, never a merge. Extensions import only from `core/index.ts` (DESIGN.md rule 2, and the import rule wiki-mind recorded for the lift). Library internals may be renamed or split without breaking them.

**QMD is an extension now (#70, #95).** The core no longer runs QMD's session-start work, and a vault's entry points no longer trigger its index refresh: the qmd extension does both, for a vault that declares it, its refresh as effects (DESIGN rule 5). To take the change on a `vendor update`, a vault:
1. deletes `core/qmd-session.ts` and `core/qmd-session.test.ts`, and their two entries under `files` in its record, by hand: `vendor update` refuses them as gone upstream until then, and `vendor record` only adds or re-records paths;
2. runs `vendor update`, which brings in the extension's two libraries, because the core's re-exports import them;
3. copies `extensions/qmd/index.ts`, `session.ts`, `refresh-run.ts`, `lib/refresh.ts`, `lib/switches.ts`, their tests and `test-fakes.ts` from mindframe at the same commit, and records them with `vendor record` and those paths;
4. adds `QMD_DECLARATION` (in `core/context.ts`) to `extensions` in `vault-manifest.json`:
   `{"id":"qmd","module":".claude/scripts/extensions/qmd/index.ts","events":["session-start","write","pre-compact","stop"]}`;
5. removes its session-start entry point's `qmdSessionStart` call, and passes `migrationNotes(manifest)` to the meter;
6. has its session-start, write, pre-compact and Stop entry points call `runEffects(registry, trigger, ctx)`, and drops their own calls to `triggerDebouncedRefresh` where it owns them. Without the session-start call, nothing starts session start's update or bootstrap, and no note says so: the manifest can't show what an entry point calls. The write entry calls it for every write, before any check that skips a file, with the written path relative to the vault, as obsidian-mind's trigger ran on the raw path. A vendored entry point that still calls obsidian-mind's copy (wiki-mind's `pre-compact.ts`) can stay: both use the sentinel `.claude/scripts/.qmd-refresh-sentinel`, so a write spawns one worker, not two.

A vault already on #70's extension takes steps 2, 3, 4 and 6: its update brings in `lib/refresh.ts` and `lib/switches.ts`, because the updated files import them, and step 3 records `refresh-run.ts` (spawned by path, not imported) and `refresh.test.ts`; step 4 is the longer `events`.

An entry point that passes `migrationNotes` shows the missing declaration on the meter line, so a vault that does step 5 and misses step 4 sees what to add. These steps were run on copies of wiki-mind 3de2fea, both from its record at mindframe bcdfc9c and from #70's migration: `vendor check` passed on all 41 files, the extension loaded from `QMD_DECLARATION` and its effects ran on all four events, and its tests passed in the vault. `VAULT_EXTENSIONS=off` now turns QMD's session-start work off too, because it is no longer core. `lib/qmd.ts` and the qmd helpers in `lib/session-start.ts` stay as re-exports of the extension's code until #96, because scripts vendored from obsidian-mind still import them there. So until #96 every vault carries the two extension libraries the core imports, `extensions/qmd/lib/qmd.ts` and `index-name.ts`, whether it declares the extension or not: `vendor update` brings them in.

The extension's two sections share one run of QMD's probes, and only render notes. The refresh is two effects: `qmd-session-refresh` at session start (an update, or the bootstrap on a missing or near-empty store) and `qmd-refresh` on a note written, before a compaction and at Stop (the debounced update and embed, in a detached worker). `disable` takes any of the four ids: a section's hides its note, an effect's stops that refresh. `enabled: false` on the declaration, or `VAULT_QMD=off`, turns it all off; `VAULT_QMD_REFRESH=off` stops every detached refresh and leaves the notes.

**`lib/session-start.ts` is not all core API.** It still carries three obsidian-mind formatters: `formatActiveWork`, `hasBrainContent` and `formatBrainIndex` (seam S2). They move out to obsidian-mind's own extensions when obsidian-mind adopts mindframe (Phase 4), not before, because obsidian-mind still calls them from this file. Don't build on them ([#46](https://github.com/breferrari/mindframe/issues/46)).

## Where it came from

The core was prototyped in wiki-mind and lifted here unmodified. `lib/fences.ts` is mindframe's own (#77), and `vendor update` brings it in for a vault whose record lacks it, because `wikilinks` and `prose-width` import it (#78). [`VENDOR.json`](VENDOR.json) records the lift: every lifted file (the core, its libraries, and the libraries' tests) at wiki-mind `3ce7381`, under `.claude/scripts/`, with 0 files modified. `lib/atomic-write.ts` joined later (#75), lifted from the same commit so that extensions can import an atomic write, and has been mindframe's own since #79 (a Windows rename retry and dotted, randomised temp files); its record entry is history like the rest. Its tests are mindframe's: `tests/atomic-write-retry.test.ts`, and `core/index.test.ts`, which tests each export extensions rely on. `vendor update` brings it in for a vault whose record lacks it, because `core/index.ts` imports it (#78). `core/context.ts` is mindframe's own, written after the lift. It is history, not a live check. From the lift on, mindframe is the upstream: the core changes here, and vaults vendor it from here. `lib/frontmatter-block.ts` is mindframe's own (#82), and `vendor update` brings it in, because `session-start`, `frontmatter`, `prose-width` and `wikilinks` import it. `lib/manifest.ts` is mindframe's own (#52), the one parse of the manifest, and `vendor update` brings it in, because the registry, `context` and `types` import it (#78). `core/qmd-session.ts` moved to the qmd extension as `extensions/qmd/session.ts` (#70), and `lib/qmd.ts` and the qmd helpers moved there too; their record entries are history. `lib/instruction-files.ts` came from obsidian-mind 74b09bc (#89), with the comments obsidian-mind's #333 changed in `session-start`, `frontmatter` and `wikilinks`, so the core's copies and obsidian-mind's agree. mindframe owns it from here: its list of retired files is frozen, and the obsidian-mind references in its comments say so, and `vendor update` brings it in, because `core/index.ts` imports it (#78).
